# 写读板 v1.5.3 发布说明

> 发布日期：2026-10-29
> 基于：v1.5.2
> 包名：`com.writeread.handwritten`（Gradle namespace 覆盖所致，与旧 `com.shiyu.hccr` 同应用）

## 一、为什么有这个版本

用户真机反馈：在「设置 → 文本转语音」选了**讯飞语音引擎**后，写字不再朗读；选**豆芽 TTS** 正常。
语音库列表已能正常显示（v1.5.1 修复生效），问题出在"部分引擎初始化成功但 `speak()` 静默失败、不回调"。

## 二、修复内容

- `TtsManager` 新增 **出声超时检测（3 秒）**：`speak` 后若未收到 `onStart`（引擎真正开始播放），
  判定该引擎未出声。
- **自动回退系统默认引擎**朗读，并提示「所选语音库无法朗读，已改用系统默认语音。可在设置→文本转语音改选其他可用语音库」。
- **会话失效记忆**：首次失灵的引擎记入本会话失效表，之后直接回退不再空等；重启 App 后清空。
- 设置页「测试中文/英文朗读」同源逻辑，选了不能用的引擎当场提示。
- 提示文案优化（`tts_unavailable`）。

## 四、升级指引

沿用原签名，可直接覆盖安装旧版（v1.5.0/1.5.1/1.5.2）。

```
adb install -r 写读板-v1.5.3-release.apk
```

## 五、验证要点

- 选「豆芽 TTS」→ 测试朗读 → 能出声；
- 选「讯飞语音引擎」→ 测试朗读 → 约 3 秒后弹"无法朗读，已改用系统默认"并听到系统默认声；
- 改回「跟随系统默认」→ 书写朗读恢复正常。

## 六、已知情况（非 App 缺陷）

讯飞语音引擎在本机通过系统 TTS 框架向第三方 App 提供播放时普遍静默失败（需自身 App 授权/联网）。
这是引擎兼容性问题，App 已做自动回退保底；建议改用系统默认或已验证可用的引擎（如豆芽 TTS）。
